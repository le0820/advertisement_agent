结论：**是的，继续完善工作流之前，应该先重新 review 内置模板库；但不是只 review 分镜文案模板，而是要把“类目体系 + brief 结构 + 评分硬门槛 + 人物约束”一起重审。**

这次高定西装输出暴露的是系统性问题，不是单条 prompt 偶然跑偏。

## 1. 高定西装：结果和预期不一致

它有一部分是合理的：
系统选择“产品感官特写”，用刺绣、钉珠、面料、光影来表现工艺，这和“高定/轻奢/手工刺绣”的品牌大片方向并不冲突。你之前设想的品牌大片路线，本身也包含“绣针、金线、工坊、材质视觉诗、工艺神话”这些元素。

但最终输出明显偏了：

第一，**类目错了**。高定西装的 `creative_brief.category` 被定位成了“珠宝饰品”，而不是“高定时装 / 礼服 / 服装鞋包”。package 里明确写的是“不对称金绣白色礼服西装”，但 category 却是“珠宝饰品”。 这会把后续模板、创意路线、评分倾向全部带偏。

第二，**它把“避免人脸风险”扩大成了“禁止人物/禁止手部/只上人台”**。最终提示词写成“无人物，仅米白半身人台穿着礼服”，负面约束又写“全程不出现人脸或人像……不可生成手部”。 这对珠宝台面广告是合理的，但对服装广告很危险，因为服装的核心价值不只是材质，而是**上身版型、场合表现、身份感、动态姿态**。

第三，**评分器明知它缺少穿着场景，却仍然给了高分**。高定西装的评分弱点里已经指出“没有植入婚礼、晚宴等使用场景”“没有直观展示版型上身效果”，但它仍然拿到 overall=90，并被推荐 render。 这说明当前评分体系把“生成稳定性”放得太重，而没有把“服装必须展示穿着效果”设为硬约束。

## 2. timefall_ring：结果基本符合预期

timefall_ring 的输出明显更稳定。它本来就是“珠宝饰品 / 情侣对戒”，brief 里也有明确的目标人群、痛点、使用场景和 CTA：30-40岁送礼男性、怕撞款、纪念日赠礼、点击定制专属对戒。

最终选中的“节日/仪式感”路线也合理：开盒、烛光、男士手部、不露脸、蓝宝石冷光、定制私语、CTA，都服务于“纪念日送礼”的购买动机。 它有手部畸变和刻字乱码风险，但系统把风险识别为 medium，并给出了规避策略，这符合“视频积分前置决策”的目标。

所以问题不是整个系统都错，而是：**当商品落在模板库覆盖范围内，系统表现可以；当商品落在模板库缺失类目时，它会被错误吸附到相近类目，然后沿着错误类目的安全策略一路决策。**

## 3. 根因判断

### 根因一：模板库类目太窄

当前模板库主要是“珠宝饰品、消费电子、汽车出行”这类结构。模板使用逻辑是“LLM system 指令 = template.system + template.scenes + template.rules + dense_caption”，也就是说，一旦类目错，后续创意逻辑就会被错误模板污染。

而特征提取 prompt 又要求 category 必须从给定类目体系中选一个，不能自创。 如果类目体系里没有“服装 / 礼服 / 高定西装”，模型只能在已有类目里找最近的。高定西装有金绣、钉珠、金属光泽，于是被吸到“珠宝饰品”，这是可以预见的。

### 根因二：`avoid_face_generation` 被错误解释成 `avoid_person`

高定西装 brief 里约束是 `avoid_face_generation: true`，但最终 prompt 变成“全程不出现人脸或人像”“不可生成手部”。

这中间少了一个关键区分：

```text
避免人脸 ≠ 避免人物
避免人脸 = 可以用不露脸模特、背影、半身、脖子以下、走秀侧影、手部工艺镜头
```

服装广告里，完全无人像会损失商品最关键的信息：版型、垂坠、肩线、腰线、行动姿态、社交场合表现。

### 根因三：评分器奖励了“安全”，但没有惩罚“服装商业信息缺失”

当前评分维度里，`seedance_feasibility` 明确要考虑复杂手部、多人、真实人脸、产品漂移等风险。 render decision 也要求优先考虑视频模型生成可行性，避免推荐高风险候选浪费积分。

这个设计本身没错。但对服装类目来说，必须加入类目硬门槛：

```text
如果 category = 服装 / 礼服 / 高定西装：
- 至少一个镜头必须展示上身效果
- 至少一个镜头必须展示使用场合
- 如果没有穿着效果，product_clarity 不能高于某个上限
- 如果没有场景关联，commercial_intent 不能高于某个上限
```

否则评分器会天然偏向“人台 + 微距 + 光影 + 无人像”的低风险方案。

## 4. 是否应该先 review 模板库？

**应该，而且优先级高于继续加视频解析模块。**

现在继续加 Video Distiller、热点搜索、更多 candidate、更多评分维度，都可能是在错误类目基础上放大错误。你需要先修“地基”。

我建议按这个顺序改：

### P0：扩展类目体系

至少新增：

```text
服装鞋包
- 高定礼服
- 男士西装
- 婚礼礼服
- 晚宴礼服
- 旗袍 / 中式礼服
- 女装连衣裙
- 鞋履
- 箱包
```

并且在 extraction 后加一个冲突检测：

```text
如果 product_name / dense_caption 出现：
西装、礼服、婚纱、裙、旗袍、外套、衬衫、面料、版型、袖口、肩线、收腰

但 category = 珠宝饰品

则标记为 category_conflict，不允许直接进入 creative_search。
```

### P1：给模板加“类目必备展示规则”

服装模板不能只写镜头氛围，必须带硬规则：

```text
服装类广告必须展示：
1. 材质细节
2. 上身版型
3. 使用场景
4. 动态姿态
5. 最终完整轮廓
```

高定西装可以有工艺微距，但不能全片都是工艺微距。更合理的结构是：

```text
0-3s：刺绣/面料微距 hook
3-6s：工坊或定制细节
6-10s：不露脸模特上身，展示肩线、腰线、行走姿态
10-13s：婚礼 / 晚宴 / 舞会 / 品牌活动场景
13-15s：完整服装 + slogan / CTA / 品牌落版
```

### P2：拆开人物约束

把现在的：

```json
"avoid_face_generation": true
```

升级成：

```json
"person_policy": {
  "face_allowed": false,
  "human_body_allowed": true,
  "hands_allowed": true,
  "model_required": true,
  "allowed_body_framing": ["back view", "side profile without face", "neck-down", "torso", "hands", "runway silhouette"]
}
```

这样系统就不会把“避免脸”误读成“禁止人”。

### P3：给评分器加类目硬门槛

对服装类加入：

```text
worn_display_score
occasion_fit_score
silhouette_clarity_score
```

并设置规则：

```text
如果是服装类：
- 没有上身展示，product_clarity 最高 65
- 没有使用场景，commercial_intent 最高 70
- 没有展示版型，render_recommendation 不能是 render，只能是 revise 或 shortlist
```

这会直接阻止“人台微距片”被选成最终方案，除非用户明确选择“产品工艺大片 / 不展示真人”。

### P4：模板库要从“行业模板”升级成“Route Library”

现在模板更像静态分镜范式。下一步应该把每个模板加元数据：

```json
{
  "template_id": "fashion_haute_couture_001",
  "category": "服装鞋包",
  "sub_category": "高定礼服",
  "best_for": ["品牌大片", "婚礼礼服", "晚宴礼服"],
  "required_visual_proofs": ["上身版型", "刺绣工艺", "场合表现"],
  "allowed_person_policy": ["no-face model", "back view", "neck-down"],
  "disallowed": ["纯人台全片", "无穿着效果", "错误珠宝化表达"]
}
```

## 5. 我对这两个结果的最终判断

**timefall_ring：符合预期，可以作为当前系统成功样例。**
它的类目、brief、痛点、场景、CTA 和最终创意是闭环的。

**高定西装：不符合你的商业预期，但符合当前系统的错误激励。**
它不是模型突然“犯傻”，而是系统在以下链路上连续偏移：

```text
服装商品
→ 被迫归入珠宝饰品
→ 珠宝式微距工艺模板被激活
→ avoid_face 被扩大为 no_person
→ 评分器奖励低风险和产品特写
→ render_decision 选择最稳但不最会卖的方案
```

所以你的直觉是对的：**先 review 内置模板库，而且要把 review 范围扩大到类目体系、brief schema、约束语义和评分硬门槛。**

我的建议是：下一步不要先接视频解析模块。先把“服装鞋包 / 高定礼服”这条类目完整跑通，再用高定西装作为回归测试样例。判定标准很简单：同一张图重新跑后，最终推荐方案必须至少包含一个“不露脸模特上身 / 走秀 / 婚礼晚宴场景”的镜头，而不是只停留在人台和刺绣微距。
